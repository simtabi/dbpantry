Roles

{{if $ha}}ha profile on{{else}}ha profile off{{end}}
Primary
Accepts writes. HAProxy write port (or Service pg on Kubernetes) follows the current leader.
Replica
Streaming copy for reads. HAProxy read port (or pg-ro) balances over healthy replicas; writes are refused.
{{if $ha}} The ha profile replaces standalone pg on this host (one write port). Run Cluster status for topology and lag, then failover or rebuild a replica from Operate actions below. {{else}} Start with profiles ha (optionally ha,pooler). That boots a 3-node Patroni cluster with etcd and HAProxy — a rehearsal topology on one machine, not multi-host production HA. {{end}}

Several engines at once

One stack runs Cassandra, MySQL, MariaDB, PostgreSQL and the rest concurrently when their profiles are in MDB_PROFILES (comma list). Start them together from Engines or Configuration — each keeps its own ports, volumes and projects.
{{actionButton . "stack.up" "Start several engines…" "class=btn-sm btn-primary" "icon=play"}} Manage profiles

Several stacks at once

Concurrent stacks are separate instance homes (MDB_HOME / Environments): each has its own project name, network subnet (auto-picked if busy) and volumes. Use Environments to init or switch.
{{t . "nav.envs"}}

Other engines

MySQL / MariaDB replication is documented as a runbook, not automated like Patroni. Cassandra and MongoDB use their own clustering models — see the operators and pooling guides.
