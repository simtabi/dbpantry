{{icon "network"}} How this stack is reached

MDB_PUBLISH={{$s.Endpoints.Publish}}
none {{if eq $s.Endpoints.Publish "none"}}current{{end}}
No host port at all, so nothing can collide with software already on the machine. Applications join {{$s.Network}} and connect by service name.
direct {{if eq $s.Endpoints.Publish "direct"}}current{{end}}
Each engine gets a port on 127.0.0.1 from MDB_PORT_BASE, for GUI clients and tests on this machine.
proxy {{if eq $s.Endpoints.Publish "proxy"}}current{{end}}
The same ports, served through the front-door proxy.

Change it in {{base $s.Endpoints.EnvFile}}, not on the command line (dbpantry refuses MDB_PUBLISH set outside that file), then run make up again.

{{icon "lock"}} TLS

Engines that always use TLS want sslmode=verify-full, the only mode that checks the host name. The others require TLS in the prod profile. Either way, point the client at the toolkit CA:

{{icon "terminal"}} Shells and next steps

A shell in an engine
make help lists one per engine, for example make psql. They work whatever MDB_PUBLISH says.
A new project
make new-project NAME=myapp ENGINE=<engine>
Everything at once
make start PROFILES=<engines> PROJECTS=myapp boots, provisions and opens this dashboard.
Every endpoint, for scripts
dbpantry endpoints -o json or /api/status
